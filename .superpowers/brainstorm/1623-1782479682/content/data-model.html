第二节：数据模型

SQLite 单文件 · 6 张核心表 · WAL 模式

表结构总览

📁 groups — 分组表
管理便签分组（工作/学习/草缸等）
id TEXT PK — UUID
name TEXT NOT NULL — 分组名称
sort_order INTEGER DEFAULT 0 — 排序权重
created_at TEXT — ISO 8601
updated_at TEXT — ISO 8601
📝 notes — 便签主表
所有类型便签（普通/待办/计时）统一存储于此
id TEXT PK — UUID
group_id TEXT FK → groups.id
type TEXT NOT NULL — 'text' | 'todo' | 'timer'
title TEXT — 便签标题（可为空，普通便签可能仅正文）
content TEXT — TipTap JSON (text/todo) 或 null (timer)
bg_color TEXT — 背景色 hex，null=白色
default_text_color TEXT — 默认文字色，null=黑色
default_font_size INTEGER — 默认字号 px
created_at TEXT — ISO 8601
updated_at TEXT — ISO 8601
deleted_at TEXT — 软删除标记，非空=在回收站
💡 content 使用 TipTap 的 JSON 格式存储，支持富文本 + 待办复选框。计时便签 content=null，计时数据在 timer_state 表。
⏱ timer_state — 计时便签专属状态
计时便签的运行时状态，note_id 一对一关联
note_id TEXT PK FK → notes.id
daily_duration_minutes INTEGER DEFAULT 480 — 每日总时长（分钟），默认8h
remaining_seconds INTEGER — 当前剩余秒数
is_running INTEGER DEFAULT 0 — 是否正在计时
last_resume_at TEXT — 上次开始/继续时间 ISO 8601
tank_start_date TEXT — 开缸日期，null=未设置
auto_start_time TEXT — 自动开始时间 'HH:MM'，null=不启用
warn_before_minutes INTEGER — 提前提醒分钟数 (10/30)，null=不提醒
🔔 reminders — 提醒表
普通便签/待办便签的定时提醒
id TEXT PK — UUID
note_id TEXT FK → notes.id
remind_at TEXT — 提醒时间 ISO 8601
repeat_type TEXT — 'once' | 'daily' | 'weekly'
repeat_days TEXT — weekly时 '1,3,5' 表示周一三五，其他类型null
is_active INTEGER DEFAULT 1
💡 weekly 重复用数字表示星期: 1=周一 … 7=周日。提醒触发后 once型自动 is_active=0；重复型自动计算下次时间。
🪟 window_state — 窗口状态记忆
每条便签 + 管理面板的窗口几何信息
note_id TEXT PK FK → notes.id (或 'management-panel' 特殊值)
x INTEGER — 窗口左上角 X
y INTEGER — 窗口左上角 Y
width INTEGER — 窗口宽度
height INTEGER — 窗口高度
opacity REAL DEFAULT 1.0 — 透明度 0.0–1.0
pinned INTEGER DEFAULT 0 — 锁定位置/大小
mode TEXT DEFAULT 'desktop' — 'desktop' 置底 | 'top' 置顶
is_visible INTEGER DEFAULT 1 — 窗口当前是否可见
⚙️ settings — 应用设置 (单行 K/V)
全局配置，仅一行数据
key TEXT PK
value TEXT
典型 key: data_path (自定义存储路径), backup_path (备份路径), backup_keep_days (保留天数), trash_auto_clean_days (回收站自动清理天数), autostart (开机自启), language (语言) …

存储路径 — 支持自定义

默认路径 + 用户可改，迁移时自动处理

默认路径%APPDATA%/StickyNotes/
数据库文件{路径}/data.db (SQLite WAL 模式，含 -wal -shm 辅助文件)
备份目录{路径}/backups/ (可独立设置)
更改路径时停止所有引擎 → 复制 data.db 到新路径 → 更新设置 → 重启引擎。备份也同步迁移。

迁移与导出

📤 手动导出 JSON

Rust 读取所有表 → 序列化单个 JSON 文件。包含便签、分组、计时状态、提醒。用户可选择导出路径。

📥 JSON 导入（合并或覆盖）

读取 JSON → 验证结构 → 用户选择"覆盖"或"合并"模式 → 写入 SQLite。
